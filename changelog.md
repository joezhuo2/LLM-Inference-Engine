## kernel/add-rmsnorm-impl

- Implement `engine::fast::add_rmsnorm` (`src/kernels/add_rmsnorm.cu`, Joe's Part C): one block of 256 threads per row; each thread adds `x` and `residual` in FP32, writes the BF16-rounded sum, and accumulates the square of that rounded value; the sum of squares is reduced with a warp shuffle reduction and a shared-memory pass over the warp totals, thread 0 computes `rsqrtf(mean + eps)`, and a second pass over the row reads the rounded sum back and writes `bf16(weight * bf16(sum * rstd))`. - Add top-k sampling: `SamplingParams::top_k` (default 0, off; negative values are rejected by `validate`). After the temperature, as in HF (`TemperatureLogitsWarper`, then `TopKLogitsWarper`), only the tokens whose scaled logit `s_i = logit_i / temperature` is at least the k-th largest stay drawable, ties with the k-th value included, exactly HF's rule `scores < topk(scores, k)[-1]` (checked in transformers 5.17: `k = 2` on `[3, 2, 2, 2, 1, 0]` keeps all three 2s); the other tokens get `-inf` before the Gumbel-max argmax. - Add top-p (nucleus) sampling: `SamplingParams::top_p` (default 1, off; `validate` rejects anything outside (0, 1], NaN included). ## sampling/temperature

- Move the greedy kernel's block argmax into `src/sampling/argmax.cuh`: `block_argmax(vocab, score)` scans a strided slice of `score(i)` per thread and reduces the (value, index) pairs in shared memory with the same rule as before (larger value wins, the lower index on equal values, `-inf` everywhere gives 0), so the temperature sampler can reuse it with a different score. `greedy` now passes `score(i) = float(logits[row, i])`; its results and tests are unchanged. (Part B)
- Add `engine::sample(ids, logits, temperature, seed, step, stream)` (`include/engine/sampling/sample.h`, `src/sampling/sample.cu`), temperature sampling on the GPU with the Gumbel-max trick: for each row of BF16 `[T, vocab]` logits it writes `argmax_i(logits[i] / temperature + g_i)` with `g_i = -log(-log(u_i))` and `u_i` uniform in (0, 1), which draws exactly from `softmax(logits / temperature)` in one pass, with no exponentials, normalization or sort. The uniforms come from cuRAND's counter-based Philox4x32-10 (`curand_init(seed, row, step * vocab + i)`, header-only device API, no library to link), so the draw is a pure function of (seed, row, step, i): the same seed and step repeat exactly, and different rows, steps or seeds use disjoint parts of the stream. `u = (x + 0.5) / 2^32` for a 32-bit `x` never reaches 0 or 1, and both logs are taken in double: a first version built `u` from 24 bits in float, and the Gumbel tail it then truncated at 17.3 and quantized coarsely is exactly where the winning noise of a 32,000-token row lies (its maximum is around `log(32000) = 10.4`), which failed the chi-square test on HF's logits (71 against a critical 39). `-inf` logits are never drawn, a row of `-inf` gives 0, and the temperature must be positive and finite (greedy decoding stays `greedy`). Tests: chi-square goodness of fit against the softmax (critical value at p = 0.001, deterministic seeds) on a 7-token row at temperatures 0.25 to 2 (200,000 draws each, the masked token never drawn) and on the last prompt row of HF's stored logits of two reference prompts at temperatures 0.7, 1 and 1.5 (100,000 draws each, tokens expected fewer than 20 times pooled into one bucket); a temperature of 0.05 equals greedy when the top logit leads by 2 (more than the Gumbel range); repeating the call repeats the ids, and changing the step or the seed, or moving to another row, redraws nearly every row; bad arguments are rejected. Dropping the temperature, sampling `-log(u)` instead of a Gumbel, ignoring the step or using one stream for every row each fails the tests. (Part B)

## model/forward

- Add `engine::greedy(ids, logits, stream)` (`include/engine/sampling/greedy.h`, `src/sampling/greedy.cu`, built into `engine_kernels`), greedy decoding on the GPU: for each row of BF16 `[T, vocab]` logits it writes the index of the largest value to I32 `ids` `[T]`. One 1024-thread block per row: each thread scans a strided slice keeping its best (value, index), then a shared-memory tree reduction keeps the larger value or, on equal values, the smaller index. A row of `-inf` returns 0. - Add `engine::ModelRunner` (`include/engine/runtime/model_runner.h`), the batch-1 forward pass over the naive kernels and a contiguous KV cache. The constructor takes the config, the device weights, `max_tokens` (the most tokens one `forward` call takes) and `max_context` (the KV cache length, at most `max_positions`), and allocates everything up front: a 32 MiB cuBLAS workspace and `Blas` handle, one buffer per activation sized for `max_tokens` rows (hidden, normed, fused QKV, attention output, projection, fused gate and up, SwiGLU output, logits), the token ids and positions, and the K and V caches of all 22 layers (`[max_context, kv_heads * head_dim]` each, 46 MB at 2,048). `forward(ids, all_logits, hook)` appends `ids` at positions `length()` to `length() + T - 1`: embedding, then per layer RMSNorm, the fused QKV GEMM, RoPE, `store_kv`, attention, the output GEMM and the residual add in place, RMSNorm, the fused gate and up GEMM, SwiGLU, the down GEMM and the second residual add, then the final norm and `lm_head`. - Add `engine::naive::attention(out, qkv, k_cache, v_cache, start, heads, kv_heads, stream)`, causal grouped-query attention for batch 1 over the contiguous cache: query `t` of the fused `[T, (heads + 2 * kv_heads) * head_dim]` input sits at position `start + t` and attends to cache rows `0` to `start + t`, so the same call covers prefill (`start = 0`, `T` tokens) and decode (`T = 1`); the caller stores the new K and V first with `store_kv`. Query head `h` reads KV head `h / (heads / kv_heads)`. One 256-thread block per (token, head) holds the query and one score per context position in dynamic shared memory (the launcher rejects contexts that do not fit in 48 KB, about 12,000 positions at `head_dim` 64; TinyLlama's limit is 2,048) and reproduces HF's eager BF16 arithmetic step by step: each score is an FP32 dot product rounded to BF16 and then scaled by `1 / sqrt(head_dim)` and rounded again (exact for 64); softmax in FP32 with `expf` and rounded to BF16, as `softmax(..., dtype=float32).to(bfloat16)` does; then the FP32 weighted sum of V rounded to BF16. The max and the sum are taken serially by one thread, which is slow but gives a fixed order. A CPU reference with the same roundings and the same `fma` order matches on four head layouts (including MHA and a single KV head) at up to 300 tokens except where CUDA's `expf` (up to 2 ulps off) and glibc's differ: that flips the BF16 rounding of a few probabilities, and cancellation in a weighted average of random values can turn one flip into hundreds of ulps of a small output. With correctly rounded `exp` on both sides the match was exact, so the test allows each element to be off by `2^-7 * (sum_j p_j |v_j| + |out|)`, the effect of every probability flipping by one ulp, on at most 0.1% of elements. Exact tests: decoding one token at a time after a 13-token prefill equals one 40-token prefill, a single token returns its own V head (which pins the GQA mapping), and garbage in cache rows past the query position does not change the result. Making every head read KV head `h % kv_heads`, dropping the causal limit, or skipping the probabilities' BF16 rounding each fails the tests. (Part B)

SentencePiece always adds the prefix, so each segment is encoded as `"\n" + segment` and the first two ids (the prefix and the `<0x0A>` byte piece, which BPE never merges with its neighbours) are dropped; the constructor rejects a model where `"\n"` does not encode that way. `decode(ids)` skips BOS, EOS and UNK like `skip_special_tokens=True` and rejects out-of-range ids. A Python prototype of these rules matched HF on 20,029 fuzzed strings (encode) and 5,000 decodes; the unit tests pin HF's ids for plain text, leading spaces, special-token text, emoji and CJK, and skip without the model. The SentencePiece header stays out of the public header (forward declaration plus `std::unique_ptr`). The fetched `sentencepiece-static` target is now built (it is linked for the first time) and compiled with `-w`, because its own code trips GCC 13's `-Wstringop-overflow`. (Part A)
- Add `chat_prompt(messages, add_generation_prompt)` (`include/engine/tokenizer/chat.h`), TinyLlama's Zephyr-style chat template rendered exactly as transformers renders its Jinja template: each message becomes `<|role|>\n` + content + `</s>\n`, and the generation prompt `<|assistant|>\n` follows the last message (none when there are no messages). Roles other than system, user and assistant throw instead of being silently dropped as the template would. Encoding the result with `add_bos = false` gives the same ids as `apply_chat_template(..., tokenize=True)`, which adds no BOS; a test pins those 16 ids for a one-message conversation. (Part A)
- Add `scripts/tokenizer_golden.py --model <dir> --out tests/golden/tokenizer.json`, which records HuggingFace's ids (with BOS) and `skip_special_tokens` decode for 28 hand-written edge cases and 5,000 seeded random strings over an alphabet heavy in spaces, newlines, angle brackets, special-token text and multi-byte characters, and `TokenizerGolden.MatchesHuggingFace`, which requires `Tokenizer` to reproduce every one (reporting the first 10 mismatches). - Add `scripts/prompts.json`, the 20 fixed chat prompts of the M2 correctness criteria (short facts, code, arithmetic, lists, a story, translation with accents, emoji and non-Latin scripts, system prompts and one multi-turn conversation), and `scripts/dump_reference.py --model <dir> --out tests/golden/reference`, which runs HF TinyLlama in BF16 with eager attention, greedily generates up to 64 tokens per prompt, then runs one forward pass over prompt plus continuation and writes `<name>.safetensors` per prompt: `input_ids` (I32), `embed`, `layers.{i}.out` for all 22 layers, `final_norm` and BF16 `logits`, captured with forward hooks. One traced prompt (default the first) also gets every layer's `ln1`, `q`, `k`, `v` (before RoPE), `attn`, `o`, `ln2`, `gate`, `up`, `act` and `down`, for debugging the forward pass one operation at a time. `manifest.json` records versions, device, the tensor meanings, and per prompt the messages, lengths, generated ids and text. (Part A)
